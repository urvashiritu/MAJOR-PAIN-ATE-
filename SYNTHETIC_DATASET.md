# Synthetic Authentication Log Datasets

**AI-Based Identity Anomaly Detection System**

The objective of these datasets is to simulate authentication logs generated by different enterprise systems so that we can develop, test, and evaluate a platform-independent authentication anomaly detection pipeline.

> **Note:** These datasets are synthetic and are inspired by publicly documented authentication log formats. They do **not** contain any real user or enterprise data.

---

# Why Synthetic Data?

Obtaining real authentication logs from organizations is extremely difficult because they contain sensitive information such as:

- User identities
- IP addresses
- Device information
- Authentication history
- Organization infrastructure

Due to privacy, security, and compliance requirements, such datasets are rarely available publicly.

Therefore, we generated realistic synthetic datasets that closely resemble real authentication logs while remaining completely safe to share and use for research.

---

# Why Multiple Log Sources?

Modern organizations use multiple authentication systems.

Examples include:

- Web Applications
- Company Portals
- Linux SSH Servers
- Windows Active Directory
- VPN Gateways
- AWS Cloud Console
- Microsoft 365 / Entra ID
- Database Servers

Each platform generates logs in a different format.

For example:

```
SSH
↓

Jul 30 10:30:22 server sshd: Accepted password...
```

```
AWS
↓

JSON
```

```
Windows AD
↓

Event Logs
```

```
Microsoft 365
↓

Sign-in JSON
```

Because of these differences, a single ML model cannot directly consume every log format.

---

# Our Approach

Instead of training separate machine learning models for every platform, our system first converts every authentication log into a common authentication schema.

```
Raw Logs
(Web / SSH / VPN / AD / Cloud)

        │
        ▼

Platform Parser

        │
        ▼

Normalized Authentication Event

        │
        ▼

Feature Engineering

        │
        ▼

Machine Learning Model
```

This architecture allows the same ML pipeline to work with multiple authentication sources.

---

# Common Authentication Attributes

Regardless of the original source, every parser extracts common attributes such as:

- User ID
- Timestamp
- Source IP
- Country
- Device
- Browser
- Operating System
- Login Success / Failure
- Authentication Source

These standardized attributes are then used for feature engineering.

---

# Behavioral Features

Examples include:

- Login Hour
- Night Login
- Weekend Login
- Country Change
- Device Change
- Failed Before Success
- Login Frequency
- Rapid Login Rate

These behavioral features are used to train the machine learning models.
