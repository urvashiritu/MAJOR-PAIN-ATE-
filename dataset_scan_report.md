# Dataset Scan Report — RBA Dataset (in plain words)

**File:** `data/raw/rba-dataset.csv` (8.5 GB, Zenodo 6782156)
**Scan date:** Aug 2, 2026 (scans 4–5 re-audited Aug 8)
**Method:** DuckDB read-only. Every query scanned **all 31,269,264 rows** (~5 s per pass).
No files were modified during the scans.

---

## TL;DR — what we found, in one paragraph

The dataset is **big (31.3M login events), real-world shaped, but synthesized**
(artificially regenerated by the authors, Wiefling et al. 2022). It has:

- **good bones** — every column parses cleanly, no duplicates, no garbage types,
- **expected messiness** — ~12% generator-bot traffic, 5.3% impossible browser versions,
  browser/OS contradictions, mostly-empty RTT, private IPs "located" in foreign countries,
- **one decisive discovery** — `Is Attack IP` is an **IP blacklist** (same IP always same
  value), which means behavior models can never predict it (see README).

Every issue was either **fixed in cleaning**, **kept as an explicit flag**, or
**deliberately left alone with a documented reason**. No rows were ever deleted.

## 3. Inconsistencies found (full-scan counts)

> **Why so many problems?** The dataset is synthesized — the generator statistically
> recreated real login patterns, and the imperfections below are artifacts of that
> generation. Each one taught us something about how to clean safely.

### 3.1 Browser ↔ OS contradictions — 1,223,315 rows (3.9%) — HIGH

| Pattern | Rows |
|---|---|
| browser says Android, OS says iOS | 1,207,424 |
| browser says mobile platform (Android/iPhone/iPad), OS says Windows | 15,644 |
| browser says Windows, OS says mobile (Android/iOS/Mac) | 247 |

Example (`data/raw/rba-dataset.csv:3`): browser `Android 2.3.3.2672` + OS `iOS 7.1`.

**What it means:** the device-change features would invent fake device switches and
confuse the models. Fix: the User Agent string is the source of truth for the OS.

### 3.2 device=mobile but browser string has no mobile marker — 3,162,207 rows (10.1%) — MEDIUM

Device Type says `mobile`, but the Browser column has no `Mobile`/`Android`/`iPhone`/`iPad`
token (e.g. browser `Firefox 20.0.0.1618`, OS `iOS 13.4`, device `mobile`).

**What it means:** the dataset's own UA-parser lost the mobile marker. Not a user-level
error; the device is re-derived from the UA string in cleaning.

### 3.3 Private (RFC1918) IPs geolocated to other countries — 5,266,810 rows — HIGH

- `10.x` private IPs: **7,291,335 rows (23.3%)** — internal IPs from Telenor's SSO
  vantage point; plausible only for NO
- of those, **5,266,810 are tagged with countries other than NO** (US, RU, …) —
  impossible geolocation
- **506,460 private-IP rows are flagged `Is Attack IP = True`** — ambiguous labels
  (a private/internal address in an external blocklist is suspicious either way; see
  the README for why we keep rather than delete these rows)
- 1,920,195 successful logins from private IPs
- 39 of the 141 ATO rows come from private IPs
- **IP reuse across users:** 49,009 IPs serve 10–99 users, 9,221 serve 100–999,
  1,071 serve 1,000+ (top: `10.0.77.226` with 12,235 users) — private NAT pools, so
  IP-derived identity signals are weak for these rows

**What it means:** a private IP can't be geolocated, so rows get a `is_private_ip` +
`geo_unreliable` flag instead of a fake country. We deliberately do NOT delete the
attack-flagged private-IP rows: an attacker on a stolen company laptop *would* be on a
private IP — that's a real scenario the model should learn.

### 3.4 Round-Trip Time missing / extreme — 29,993,329 rows — MEDIUM

- **95.9% of rows have empty RTT** (only 1,275,935 have a value). Not a parse error —
  the column is mostly empty by design.
- 79 rows have RTT > 60,000 ms (max 223,457 ms ≈ 3.7 min) — implausible outliers.

**What it means:** RTT cannot be a primary feature; it's kept as an auxiliary signal
with explicit `rtt_missing` / `rtt_outlier` flags.

### 3.5 Two missing-value conventions — 14,063,591 rows — LOW

Region/City use `-` as a placeholder **and** NULL in the same columns:

| Pattern | Rows |
|---|---|
| region `-` AND city `-` | 13,895,698 |
| region `-` but city set | 117,683 |
| region NULL | 47,409 |
| city NULL | 8,590 |

**What it means:** `-` and NULL are unified into NULL in cleaning.

### 3.6 Device type `unknown` / `bot` — 2,895,205 rows (9.3%) — LOW

- `unknown`: 867,371 rows (11,230 successful — silent gap in device coverage)
- `bot`: 2,027,834 rows (only 64 successful; 4,959 of them have non-bot User Agent strings)

**What it means:** kept as explicit categories, never silently treated as real devices.

### 3.7 ATO label quirks — 65 rows — LOW

- 1 of 141 ATO rows is a **failed** login (takeover on a failed attempt)
- 64 of 141 ATO rows are NOT flagged `Is Attack IP` — the attack-IP label alone misses
  45% of confirmed takeovers

**What it means:** this is why `is_ato` is the behavioral gold standard and the
attack-IP label is not.

### 3.8 Impossible browser/OS versions vs login date — 1,651,546 rows (5.3%) — MEDIUM-HIGH

Versions appear **before their real-world release date** (or after the dataset ends) —
a synthesis artifact, not user error:

| Impossible pattern | Rows |
|---|---|
| Chrome 85 before 2020-08-25 (release) | 7,337 |
| Chrome 89 (released Mar 2021, after dataset end) | 159 |
| Chrome 90+ (released Apr 2021+, after dataset end) | 239,712 |
| Android 11 before 2020-09-08 (release) | 38 |
| Android 12+ (released Oct 2021, after dataset end) | 885,290 |
| iOS 14 before 2020-09-16 (release) | 516,751 |
| iOS 15+ (released Sep 2021, after dataset end) | 2,259 |

> **Reproducibility note:** every count above uses the **`browser_raw` / `os_raw` columns**
> (e.g. `Chrome 85` matches `^Chrome 85`), **not** the `user_agent` column — matching the
> UA yields different numbers (e.g. `Chrome 85` in the UA → 1.18M).

**What it means:** proves the dataset is synthesized and raw version strings can't be
trusted for temporal features. Fix: use version-stripped families instead.

### 3.9 Generator-bot traffic — 3,704,894 rows (11.8%) — MEDIUM-HIGH

3.70M User Agent strings carry the generator's own URL `github.com/das-group/rba-dataset`:

| Bot UA | Rows |
|---|---|
| `ZipppBot/0.11 (... das-group ...)` | 1,662,964 |
| `Mozilla/5.0 (compatible; startmebot/1.0 ...)` | 321,325 |
| `ZoomBot (Linkbot 1.0 ...)` | 19,570 |
| `Mozilla/5.0 (compatible; MetaJobBot ...)` | 7,437 |
| Normal-looking UAs also stamped with the URL (e.g. Lumia `... das-group/rba-dataset ...`) | ~1,693,598 |

- 2,020,868 of them have `device = bot`; 349,510 carry attack-IP flags (11.3% of all),
  500,565 are "successful" logins
- The single bot user `-4324475583306591935` — 14,025,899 rows (**44.86% of ALL events**),
  4 successes, 1,650,627 attack flags = **53% of all attack flags** (a concentration
  problem; handled at sampling — capped at 50,000 rows)

**What it means:** ~12% of the dataset is the generator's own machinery. It's flagged as
`is_generator_bot` and capped at sampling — never silently trained on as normal human
behavior.

### 3.10 ASN ↔ country mismatch — 15,497,255 rows (49.6%) — MEDIUM

680 ASNs are tagged with 2+ countries; e.g. ASN 29695 (Telenor Norway) spans 6 countries
with 8,130,723 rows; ASN 500039 spans 28 countries. Real CDNs/clouds do serve multiple
countries, but ~half the dataset is too much — the synthetic geolocation generated
country independently of ASN.

**What it means:** keep ASN, trust the row's country (IP→country itself is consistent).

### 3.11 VLC media-player UAs — 708,927 rows (2.3%) — LOW

`VLC/3.0.0-git LibVLC/3.0.0-git` — a desktop video player attempting 708,927 logins,
**all failed**, 46,023 attack-flagged. A media player cannot do SSO — synthetic noise rows.
Flagged `is_vlc`.

### 3.12 Exotic leftover browser families — 713,403 rows (2.3%), 44 families — LOW

Version stripping leaves parser-artifact families: `VLC 3.0.0-git`, `134 Browser`,
`1Password`, `Unknown Mac OS X 11_6_3 Browser`, `Bot Mac OS X 11_6_3 Browser`,
`Tablet Windows Phone 8_1 Browser`. Caused by `_`-separated versions (`11_6_3`) not being
stripped — fixed by the cleaning regex.

---

**Root cause of 3.8–3.11:** the RBA dataset is **synthesized** (statistically reconstructed
from real login patterns). Versions don't respect the timeline, the generator stamped its
own URL into UAs, and geolocation was generated independently of ASN.

## 5. Cleaning solution (how we preprocess)

**Design principle:** preserve raw values for auditability; cleaning **adds normalized
columns + flags**, it never silently drops rows.

The cleaned file (`data/processed/rba_clean.parquet`, written by `src/00_clean_dataset.py`)
keeps every original value in `raw_*` columns and adds:

| New column | What it does | Fixes |
|---|---|---|
| `os_family` | The real OS, derived from the User Agent (the source of truth) | §3.1, §3.12 |
| `browser_family` | Browser name with version stripped (both `85.0.4183` and `11_6_3` forms) — 4,549 strings collapse to ~200 families | §3.12 |
| `device_type` | mobile / tablet / desktop / bot / unknown, re-derived from the UA (tablet markers checked before Mobile; token-boundary `Mobile`) | §3.2 |
| `is_private_ip` | True for `10.x`, `172.16–31.x`, `192.168.x`, `127.x`, `169.254.x` (7.29M rows) | §3.3 |
| `geo_unreliable` | Private IP OR missing region/city — deliberately NOT the same as `is_private_ip` | §3.3, §3.5 |
| `rtt_missing` / `rtt_outlier` | RTT flags; RTT > 60,000 ms is set to NULL and flagged | §3.4 |
| `ua_os_conflict` | True where derived OS differs from the raw OS column | §3.1 |
| `version_stripped` | True where a version was removed | §3.12 |
| `is_generator_bot` | UA matches `ZipppBot\|startmebot\|ZoomBot\|MetaJobBot\|das-group\|AwarioSmartBot` (3.85M rows) | §3.9 |
| `is_vlc` | UA matches `VLC` (708,927 rows) | §3.11 |

Notable cleaning details:

- **iOS detection needs a token boundary** — `(^|[^A-Za-z0-9])(iPhone|iPad|iPod|iOS)($|[^A-Za-z0-9])`
  — because bare-substring `iOS` mislabeled 134,393 AwarioSmartBot crawlers and 26,263
  CriOS-on-Android spoofs as iOS (fixed Aug 8).
- **`Andorid` typo** (242 rows) is matched by `(Android|Andorid)`.
- **Windows Phone is checked BEFORE iOS** — WP UAs carry a `like iPhone OS` spoof token.
- **Tablet markers** (`iPad`, `Tablet`, `SM-T`, `Galaxy Tab`, …) are checked before
  `Mobile` because tablet UAs carry "Mobile".

### What we deliberately do NOT fix

- The **506,460 private-IP attack flags** and the **64 un-flagged ATOs** stay as labels —
  the model decides what weight to give them (we keep the rows; deleting them would hide
  real scenarios like a stolen company laptop).
- Positive/negative User IDs — both legitimate.
- `XK` country code — keep.
- Generator-bot and VLC rows are **kept + flagged**; removal is a *sampling* decision
  (`--no-genbots` / `--no-vlc`), never a cleaning decision.
- Impossible version-vs-date rows (5.3%) — kept; features use stripped families.
- **No rows are deleted**: a cleaning job must not change the row count
  (31,269,264 → 31,269,264).

### 8.2 The one gap found — and fixed

Six **real OS families** were falling to `os_family='unknown'` because their UAs are
platform-silent and no `os_raw` fallback existed:

| Family | Rows (raw) | Rows (complete) |
|---|---|---|
| BlackBerry | 7,809 | 7,837 |
| MeeGo | 3,110 | 3,110 |
| Roku | 75 | 649 |
| Symbian | 35 | 35 |
| WebTV | 21 | 21 |
| Firefox OS | 5 | 5 |
| **Total** | **11,055** | **11,657** |

> **Why the difference:** the raw audit grouped exact `os_raw` *values* (`os_raw='Roku'`
> = 75), but version-suffixed values (`Roku 9.10`, …) were separate groups. The regex
> fallback (`(?i)Roku`) catches all of them, so the rebuilt parquet holds the **complete**
> count (11,657).

**Fix:** six `os_raw` fallback branches added to the `os_family` CASE in
`src/00_clean_dataset.py`, guard `legacy_os_rows` added to `CHECKS_CLEAN`. Parquet
rebuilt (Aug 8): `legacy_os_rows = 11,657`; remaining `unknown` = 2,884,450 (mostly the
`os_raw="Other "` junk category, deliberately unknown).

### 8.3 Observed, not defects

- **1.13M iOS-family rows whose `browser_raw` column says `Android 2.0`** etc. — generator
  slop in the *browser* column only; the UA, `os_family`, and `device_type` are all
  correct, so features are unaffected.
- Non-ASCII city/region names — normal international text.
- Hour-of-day has a strong human diurnal shape — useful for `is_night`, not an anomaly.

### 8.4 Audit-complete statement

**Every column enumerated, every mapping's coverage measured, every two-way cross-tab
checked — the only gap found (6 legacy OS families, 11,657 rows) was fixed and is now a
permanent guard. The cleaned parquet is declared audit-complete as of Aug 8, 2026.**

## 9. Audit-fix pass (Scan 5, Aug 8, 2026) — pipeline implementation audit

An independent agent audited the cleaning/sampling/feature **scripts** for
implementation-vs-doc drift (scans 1–4 were dataset-only). 10 issues found; all fixed;
all now regression-guarded by `src/03_validate_contract.py`.

### 9.1 The 10 fixes

| # | Issue | Fix | Contract guard |
|---|---|---|---|
| 1 | `geo_unreliable` was a byte-identical duplicate of `is_private_ip` | `geo_unreliable = is_private_ip OR region NULL OR city NULL` | `geo_semantics_violations` |
| 2 | `(?i)iOS` substring mislabeled 134,393 AwarioSmartBot rows + 26,263 CriOS-on-Android spoofs | Token-boundary iOS; `AwarioSmartBot` → `is_generator_bot` | `ios_spoof_label` |
| 3 | Bare `Mobile` substring reclassified 3,402 desktop rows as mobile | Token-boundary `Mobile` only when UA has no desktop-OS token | `desktop_reclass_mobile` |
| 4 | `device_raw='unknown'`/NULL short-circuited UA checks; NULL → `desktop` | UA checks run first; NULL/`unknown` → `unknown` | `null_device_desktop` |
| 5 | `Andorid` typo (242 rows) escaped Android detection | `(Android\|Andorid)` in all Android regexes | `ios_spoof_label`/`ua_os_conflict` |
| 6 | Sampling non-deterministic — `random()` not reproducible under threads | Hash-based deterministic ordering | identical rebuild |
| 7 | `fixed_rows` hardcoded (wrong by 19,762 under `--no-genbots`) | Computed at runtime from tier recomputation | check 7 (fixed-rows cross-check) |
| 8 | `prior_fail_ts` leaked into features output | Removed | `FORBIDDEN_COLS` (check 4) |
| 9 | `rn`/`is_robot_sampled` still in the training table | Dropped | schema contract (check 1) |
| 10 | `failed_before_success` misnomer — no time window | One shared `feature_sql` with a real 5-minute lookback; renamed `failed_recently` | check 8 feature sanity |

### 9.2 Status

`python src/03_validate_contract.py` passes on the rebuilt artifacts (Aug 8):
clean 31,269,264 → rba_features 31,269,264 → sample/features 1,000,003, zero forbidden
columns, zero feature NULLs, zero first-event changes. Cleaning + sampling + features
declared stable as of Aug 8, 2026.
